Kubernetes · Cheatsheet 02

kubectl

kubectl es el comando para hablar con el cluster: consultar qué hay, crear y borrar objetos, ver logs y entrar a los Pods. Casi todos los comandos siguen el patrón kubectl <verbo> <tipo> <nombre>, por ejemplo kubectl get pods o kubectl delete deploy chanchito. Lo que está entre < > se reemplaza.

Términos de esta página

Los objetos (Pod, Deployment, Service…) están explicados en Conceptos.

Recurso / objeto
Cualquier cosa que existe en el cluster: un Pod, un Deployment, un Service, un namespace. Cada uno tiene un tipo y un nombre.
Verbo
Lo que querés hacer: get (listar), describe (detalle), apply (crear o actualizar), delete (borrar), logs, exec…
kubeconfig
El archivo ~/.kube/config donde kubectl guarda a qué clusters puede conectarse y con qué credenciales.
Contexto
Una combinación de cluster + usuario + namespace guardada en el kubeconfig. Cambiar de contexto = cambiar de cluster.
Namespace
Agrupación de recursos dentro del cluster. Si no indicás uno con -n, kubectl usa default.
Label
Una etiqueta clave=valor pegada a un objeto (app=chanchito), para filtrar y agrupar.
Rollout
El proceso de actualizar un Deployment a una versión nueva, reemplazando los Pods de a poco.
Port-forward
Un túnel temporal desde un puerto de tu PC hasta un Pod o Service del cluster, para probarlo desde el navegador.
Watch (-w)
Dejar el comando abierto mostrando los cambios en vivo. Se corta con Ctrl+C.
Helm / chart
Helm es un gestor de paquetes para Kubernetes; un chart es un paquete listo para instalar (por ejemplo, una base de datos completa).

Cluster local para practicar

Elegí uno. En Windows lo más directo es el de Docker Desktop.

Docker Desktop

  1. Abrí Docker Desktop → ícono de engranaje (Settings) → Kubernetes.
  2. Marcá Enable Kubernetes y tocá Apply & restart. Si pregunta por el tipo de cluster, dejá la opción por defecto (kubeadm).
  3. Esperá unos minutos a que abajo aparezca Kubernetes running.
Esto instala kubectl y crea el contexto docker-desktop.
kubectl config use-context docker-desktop
kubectl get nodes
Apuntar kubectl a ese cluster y comprobar que responde.
NAME             STATUS   ROLES           AGE   VERSION
docker-desktop   Ready    control-plane   2m    v1.3x.x

Contextos: a qué cluster estoy apuntando

Un contexto = cluster + usuario + namespace por defecto. Viven en ~/.kube/config.

Ver y cambiar contexto

kubectl config get-contexts
Lista; el actual tiene *.
kubectl config current-context
Solo el actual.
kubectl config use-context <contexto>
Cambiar de cluster.

Namespace por defecto

kubectl config set-context --current --namespace=<ns>
Evita escribir -n en cada comando.
kubectl config view --minify
Config efectiva del contexto actual.
!

Antes de borrar algo, revisá el contexto. Es el error clásico: ejecutar en producción creyendo que estás en local.

3

Ver recursos

get para listar, describe para el detalle con eventos.

Listar (get)

kubectl get pods
Pods del namespace actual (≈ docker ps).
kubectl get pods -o wide
Con IP y nodo de cada Pod.
kubectl get pods -A
De todos los namespaces.
kubectl get pods -w
Watch: se queda mostrando los cambios.
kubectl get all
Pods, Services, Deployments, ReplicaSets (no incluye ConfigMaps, Secrets ni PVC).
kubectl get deploy,svc,pvc,cm,secret
Varios tipos a la vez.

Detalle (describe)

kubectl describe pod <pod>
Estado, contenedores, volúmenes y Events al final: ahí está el motivo de casi todo error.
kubectl describe deploy chanchito
kubectl describe svc chanchito
En un Service mirá Endpoints: si está vacío, el selector no encuentra Pods.
kubectl get events --sort-by=.lastTimestamp
Eventos del namespace en orden.
kubectl get deploy chanchito -o yaml
El objeto completo tal como lo guarda el cluster.
kubectl explain deployment.spec.template.spec.containers
Documentación de cualquier campo del YAML.
kubectl api-resources
Todos los tipos y sus nombres cortos.
4

Crear, actualizar y borrar

Lo normal: escribir YAML y usar apply. Los comandos imperativos sirven para pruebas rápidas o para generar el YAML.

Declarativo (apply)

kubectl apply -f deployment.yaml
Crea o actualiza lo que haya en el archivo. Se puede repetir sin miedo.
kubectl apply -f k8s/
Todos los YAML de una carpeta (≈ docker compose up).
kubectl diff -f k8s/
Qué cambiaría antes de aplicar.
kubectl delete -f k8s/
Borra lo definido en esos archivos (≈ compose down).
kubectl apply -k overlays/dev
Con Kustomize (variantes por entorno).

Imperativo y generadores

kubectl create deployment chanchito --image=chanchito:1 --replicas=2
Crear un Deployment sin YAML.
kubectl expose deployment chanchito --port=80 --target-port=3000
Crear su Service.
kubectl create deployment chanchito --image=chanchito:1 \
  --dry-run=client -o yaml > deployment.yaml
Truco: genera el YAML base sin crear nada.
kubectl run tmp --rm -it --image=busybox -- sh
Pod temporal para probar cosas desde adentro del cluster.
kubectl edit deploy chanchito
Edita en vivo (abre el editor). Mejor cambiar el YAML y aplicar.

Borrar

kubectl delete pod <pod>
Si es de un Deployment, se recrea (sirve como “reiniciar”).
kubectl delete deploy chanchito
kubectl delete svc chanchito
Borrar por tipo y nombre.
kubectl delete all -l app=chanchito
Todo lo que tenga ese label.
kubectl delete pod <pod> --grace-period=0 --force
Forzar un Pod trabado en Terminating.
5

Logs, entrar al Pod y acceder desde tu PC

Lo que más vas a usar para depurar.

Logs

kubectl logs <pod>
Salida del contenedor.
kubectl logs -f <pod>
En vivo.
kubectl logs deploy/chanchito
De un Pod del Deployment sin buscar el nombre.
kubectl logs -l app=chanchito --tail=50
De todos los Pods con ese label.
kubectl logs <pod> --previous
Del contenedor anterior que crasheó (clave en CrashLoopBackOff).
kubectl logs <pod> -c <contenedor>
Si el Pod tiene varios contenedores.

Entrar y copiar

kubectl exec -it <pod> -- sh
Shell dentro del Pod. El -- separa kubectl del comando.
kubectl exec -it deploy/monguito -- mongosh -u mati -p <password>
Consola de Mongo.
kubectl cp <pod>:/home/app/log.txt ./log.txt
Copiar archivos Pod ⇄ PC.
kubectl top pods
kubectl top nodes
CPU / RAM (requiere metrics-server).

Acceder desde tu PC

kubectl port-forward svc/chanchito 3000:80
localhost:3000 → puerto 80 del Service. Formato LOCAL:REMOTO, como -p de Docker.
kubectl port-forward svc/monguito 27017:27017
Conectar Compass a la base del cluster.
kubectl port-forward pod/<pod> 3000:3000
Directo a un Pod.
i

Queda corriendo en la terminal: Ctrl+C lo corta.

6

Escalar, actualizar y volver atrás

Un Deployment actualiza de a poco (rolling update): nunca te quedás sin Pods.

Rolling update de v1 a v2

kubectl set image deployment/chanchito chanchito=chanchito:2 (o cambiar la imagen en el YAML y apply)

v1 corriendo v2 terminando

Escalar

kubectl scale deploy chanchito --replicas=5
Cambia la cantidad de Pods.
kubectl autoscale deploy chanchito --min=2 --max=6 --cpu-percent=70
Crea un HorizontalPodAutoscaler (requiere metrics-server).
kubectl get hpa
Ver el autoscaler.

Actualizar y rollback

kubectl set image deployment/chanchito chanchito=chanchito:2
Nueva imagen (contenedor=imagen).
kubectl rollout status deploy/chanchito
Seguir el progreso.
kubectl rollout history deploy/chanchito
Revisiones anteriores.
kubectl rollout undo deploy/chanchito
kubectl rollout undo deploy/chanchito --to-revision=2
Volver a la versión anterior (o a una específica).
kubectl rollout restart deploy/chanchito
Recrear todos los Pods (ej. tras cambiar un ConfigMap).
7

Namespaces y labels

Organizar y filtrar.

Namespaces

kubectl get ns
Listar. Vienen default, kube-system, kube-public…
kubectl create ns chanchito-dev
Crear.
kubectl get pods -n chanchito-dev
kubectl apply -f k8s/ -n chanchito-dev
-n en cualquier comando.
kubectl delete ns chanchito-dev
⚠ Borra todo lo que hay adentro.

Labels

kubectl get pods --show-labels
Ver labels.
kubectl get pods -l app=chanchito
kubectl get pods -l 'env in (dev,qa)'
Filtrar por label (selector).
kubectl label pod <pod> env=dev
kubectl label pod <pod> env-
Agregar / quitar (con - al final).

Formatos de salida

Flag -o en cualquier get.

Tabla de -o

FlagQué muestraEjemplo
-o wideColumnas extra (IP, nodo, imagen)kubectl get pods -o wide
-o yaml / -o jsonEl objeto completokubectl get svc chanchito -o yaml
-o nameSolo tipo/nombre (para scripts)kubectl get pods -o name
-o jsonpathUn campo puntualkubectl get pod <pod> -o jsonpath='{.status.podIP}'
-o custom-columnsTus propias columnas-o custom-columns=NOMBRE:.metadata.name,IMG:.spec.containers[0].image
--sort-byOrdenarkubectl get pods --sort-by=.status.startTime
-wSeguir mostrando cambioskubectl get pods -w

Atajos y Helm

Para escribir menos.

Alias y autocompletado

# PowerShell ($PROFILE)
Set-Alias k kubectl
kubectl completion powershell | Out-String | Invoke-Expression
Después: k get po, con Tab para completar.
# Bash / Git Bash (~/.bashrc)
alias k=kubectl
source <(kubectl completion bash)
Lo mismo en Bash.
Nombres cortos: po pods · deploy · svc · ns · cm · pvc · ing · sts · no nodes.

Helm (gestor de paquetes)

helm repo add traefik https://traefik.github.io/charts
helm repo update
Agregar un repositorio de charts.
helm install traefik traefik/traefik -n traefik --create-namespace
Instalar una app empaquetada (un “chart”). Traefik sirve como Ingress controller.
helm list -A
helm upgrade traefik traefik/traefik -n traefik -f values.yaml
helm uninstall traefik -n traefik
Listar · actualizar con tus valores · desinstalar.

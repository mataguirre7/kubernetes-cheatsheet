Kubernetes · Cheatsheet 00

Empezar con Kubernetes desde cero

Una guía para hacer en orden, en Windows, sin servidores ni cuentas en la nube. Vas a activar el Kubernetes que trae Docker Desktop, correr tu primera app, abrirla en el navegador, multiplicarla, ver cómo se recupera sola cuando algo falla y, al final, describirla en un archivo como se hace en proyectos reales. Cada paso explica qué hace y muestra lo que deberías ver.

Términos de esta página

Con más detalle en Conceptos.

Cluster
El grupo de máquinas que maneja Kubernetes. En esta guía es una sola: tu PC, a través de Docker Desktop.
Nodo
Cada máquina del cluster. Acá hay uno, llamado docker-desktop.
kubectl
El comando para darle órdenes al cluster. Viene instalado con Docker Desktop.
Pod
La unidad mínima que corre Kubernetes: envuelve uno o más contenedores.
Deployment
Un objeto que dice “quiero N copias de este Pod, con esta imagen”. Kubernetes las crea y las mantiene vivas.
Réplica
Cada copia de un Pod.
Service
Un nombre y una dirección fijos para llegar a los Pods, aunque cambien.
Manifiesto
Un archivo YAML que describe lo que querés que exista en el cluster.
Imperativo / declarativo
Imperativo: dar órdenes sueltas (“creá esto”, “escalá aquello”). Declarativo: describir en un archivo cómo tiene que quedar todo y aplicarlo. En proyectos reales se usa el declarativo.
0

Requisitos

Necesitás Docker Desktop instalado y funcionando (en la colección de Docker, la hoja “Empezar desde cero” explica cómo). Si docker version muestra las secciones Client y Server, estás listo.

Conviene conocer lo básico de Docker (imagen, contenedor, puerto), porque Kubernetes corre contenedores Docker: lo que cambia es quién los administra.

1

Activar el cluster de Docker Desktop

Una sola vez.

  1. Abrí Docker Desktop y entrá a Settings (ícono de engranaje arriba a la derecha).
  2. En el menú de la izquierda, elegí Kubernetes.
  3. Marcá Enable Kubernetes. Si te deja elegir el tipo de cluster, dejá el predeterminado (kubeadm): es el que comparte las imágenes con tu Docker.
  4. Tocá Apply & restart y aceptá si pide instalar componentes.
  5. Esperá unos minutos: la primera vez descarga varias imágenes. Abajo a la izquierda tiene que aparecer Kubernetes running (o un ícono de Kubernetes en verde).
i

Este cluster corre adentro de Docker Desktop: si cerrás Docker Desktop, el cluster también se detiene. Para apagarlo sin cerrar Docker, desmarcá Enable Kubernetes.

2

Verificar que kubectl llega al cluster

En una terminal nueva (PowerShell o la de VS Code).

kubectl config current-context
kubectl puede conocer varios clusters; el contexto es el que está usando ahora. Tiene que decir docker-desktop. Si dice otro: kubectl config use-context docker-desktop.
docker-desktop
kubectl get nodes
Lista las máquinas del cluster. Ready significa que el nodo está listo para correr Pods.
NAME             STATUS   ROLES           AGE   VERSION
docker-desktop   Ready    control-plane   5m    v1.3x.x
kubectl get pods -A
Lista todos los Pods de todos los namespaces (-A). Vas a ver los del propio Kubernetes, en el namespace kube-system: es normal que existan. Los tuyos van a ir en default.
✕

Si aparece “Unable to connect to the server” o “connection refused”, el cluster todavía está arrancando o no se activó. Revisá que Docker Desktop diga Kubernetes running.

3

Tu primera app en el cluster

Un servidor web nginx, creado con un comando (forma imperativa).

kubectl create deployment web --image=nginx:1.27
Crea un Deployment llamado web que usa la imagen nginx:1.27. Kubernetes descarga la imagen y crea un Pod con ella. Es parecido a docker run, pero quien vigila el contenedor ahora es Kubernetes.
deployment.apps/web created
kubectl get deployments
Lista los Deployments. READY 1/1 = quería 1 Pod y tiene 1 listo. Si dice 0/1, esperá unos segundos (está descargando la imagen).
NAME   READY   UP-TO-DATE   AVAILABLE   AGE
web    1/1     1            1           20s
kubectl get pods
Lista los Pods. El nombre lo inventa Kubernetes: el del Deployment más dos sufijos al azar. STATUS Running = el contenedor está corriendo.
NAME                   READY   STATUS    RESTARTS   AGE
web-7d4c8b9f6d-x2k4p   1/1     Running   0          25s
kubectl describe pod <nombre-del-pod>
Todo el detalle de un Pod. Lo más útil está al final, en Events: la historia de lo que pasó (se programó en un nodo, descargó la imagen, arrancó el contenedor). Copiá el nombre exacto de kubectl get pods.
4

Abrirla en el navegador

El Pod tiene una dirección dentro del cluster, pero desde tu PC todavía no se puede entrar. La forma más rápida de probar es un port-forward: un túnel temporal entre un puerto de tu PC y el Pod.

kubectl port-forward deployment/web 8080:80
Conecta el puerto 8080 de tu PC con el puerto 80 del Pod (donde escucha nginx). Igual que en Docker, el formato es tu PC : destino. El comando queda corriendo mientras uses el túnel.
Forwarding from 127.0.0.1:8080 -> 80
Forwarding from [::1]:8080 -> 80
  1. Abrí http://localhost:8080: aparece “Welcome to nginx!”.
  2. Volvé a la terminal y cortá el túnel con Ctrl+C. La app sigue corriendo en el cluster; solo se cierra el acceso desde tu PC.
i

El port-forward es para probar. Para dejar una app accesible de forma permanente se usa un Service, que es lo que vas a hacer en el paso 6.

5

Escalar y ver la autocuración

Las dos cosas que Docker solo no hace.

Tres copias en vez de una

kubectl scale deployment web --replicas=3
Cambia la cantidad deseada de réplicas a 3. Kubernetes crea las dos que faltan.
kubectl get pods
NAME                   READY   STATUS    RESTARTS   AGE
web-7d4c8b9f6d-x2k4p   1/1     Running   0          3m
web-7d4c8b9f6d-7hq9z   1/1     Running   0          5s
web-7d4c8b9f6d-mv2rt   1/1     Running   0          5s

Borrar un Pod “por accidente”

kubectl delete pod web-7d4c8b9f6d-x2k4p
Borra uno de los Pods (usá un nombre de tu lista).
kubectl get pods
Vuelve a haber 3: uno es nuevo (otro nombre y AGE de pocos segundos). El Deployment dice “quiero 3”; al ver que había 2, creó otro. Eso es la autocuración: si un Pod se cae o una máquina falla, Kubernetes lo reemplaza solo.
✓

Por eso, para apagar una app no se borran sus Pods: se borra (o se escala a 0) el Deployment.

6

Lo mismo, con un archivo (forma declarativa)

Así se trabaja en proyectos reales: el archivo se guarda en Git y se aplica cuantas veces haga falta.

a) Borrar lo creado a mano

kubectl delete deployment web
Borra el Deployment y, con él, sus Pods.

b) Crear el archivo web.yaml

En cualquier carpeta, con tu editor. Son dos objetos en un mismo archivo, separados por ---:

# 1) Deployment: qué correr y cuántas copias
apiVersion: apps/v1
kind: Deployment
metadata:
  name: web
spec:
  replicas: 2
  selector:
    matchLabels:
      app: web     # sus Pods: los de esta etiqueta
  template:        # el molde de cada Pod
    metadata:
      labels:
        app: web
    spec:
      containers:
        - name: nginx
          image: nginx:1.27
          ports:
            - containerPort: 80
---
# 2) Service: cómo llegar a esos Pods
apiVersion: v1
kind: Service
metadata:
  name: web
spec:
  type: NodePort
  selector:
    app: web       # a qué Pods manda tráfico
  ports:
    - port: 80
      targetPort: 80
      nodePort: 30080  # puerto en tu PC

c) Aplicarlo

kubectl apply -f web.yaml
Lee el archivo y crea (o actualiza) lo que describe. -f = file, el archivo a leer.
deployment.apps/web created
service/web created

Abrí http://localhost:30080: el Service de tipo NodePort deja la app accesible sin túnel y reparte las visitas entre las 2 réplicas.

d) Cambiar y volver a aplicar

Cambiá replicas: 2 por replicas: 4 en el archivo, guardá y aplicá de nuevo:

kubectl apply -f web.yaml
Kubernetes compara el archivo con lo que existe y cambia solo lo necesario.
deployment.apps/web configured
service/web unchanged
i

Cada parte de este archivo está explicada en Manifiestos YAML; los tipos de Service, en Red, config y datos.

7

Ver logs y entrar a un Pod

kubectl logs deployment/web
Muestra lo que imprimió el contenedor de uno de los Pods del Deployment (nginx registra cada visita). Agregá -f para seguir viéndolos en vivo; Ctrl+C para salir.
kubectl exec -it deployment/web -- sh
Abre una terminal dentro de uno de los Pods. -it conecta tu teclado; el -- separa las opciones de kubectl del comando a ejecutar adentro (sh). Probá ls y salí con exit.
8

Limpiar y siguientes pasos

kubectl delete -f web.yaml
Borra todo lo que creó ese archivo (el Deployment, sus Pods y el Service).
deployment.apps "web" deleted
service "web" deleted
